## 1. 四要素

### 1.1 范围（Scope）

**做**：

| # | 内容 |
|---|---|
| S1 | 一码（QR + 短码）生成与校验：绑定用户 id + 板块 scope + 有效期 |
| S2 | 准入校验接入：中转站（exchange）、社区发帖、任务接发三个入口 |
| S3 | 管理端：生成/吊销/续期、使用记录（谁在何时用码做了什么） |
| S4 | 审计联动：生成/吊销/异常使用写入 console 审计（复用 11 字段） |
| S5 | 最小 UI：一码展示页（含倒计时）+ 扫码后落地提示 |

**不做**（明确边界）：

| # | 不做 | 原因 |
|---|---|---|
| N1 | 不接支付/扣费 | 属资金域，需单独立项 |
| N2 | 不替代 license（LV0/LV1） | license 是授权底座，一码是**准入凭证**，不得越权提升等级 |
| N3 | 不做生物识别/实名认证 | 合规与隐私成本高 |
| N4 | 不做跨机构互通 | 无接口与协议基础 |

### 1.3 验收标准（Acceptance）

| # | 验收项 | 通过标准 | 验证方式 |
|---|---|---|---|
| A1 | 一码生成 | 绑定用户+scope+有效期，重复生成不串号 | 单元测试 + 手工 |
| A2 | 校验正确性 | 过期/吊销/scope 不符 → 拒绝且给出明确错误码 | 用例矩阵（≥12 例） |
| A3 | 三入口接入 | 中转站/社区/任务均可用一码准入，且**不绕过 LV/P 权限** | 集成测试 |
| A4 | 审计完整 | 生成/吊销/异常使用 100% 入审计，字段齐全 | 审计查询比对 |
| A5 | 管理端可用 | 吊销后 5 秒内生效 | 真机计时 |
| A6 | 回归 | 回归套件 **41 → 49 套全绿**（新增 8 套） | CI 输出 |
| A7 | 安全 | 短码不可枚举（≥8 位 base32 + 频控）；日志不落明文码 | 安全自查清单 |
