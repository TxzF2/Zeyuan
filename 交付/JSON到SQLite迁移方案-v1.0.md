## 2. 迁移步骤（可执行，含验收点）

> 总窗口：**≤10 分钟**（含备份与验证）。全程 JSON 原文件不删。

### S0 · 前置门禁（迁移前 1 天）

| 步骤 | 命令/动作 | 验收点 | 失败处理 |
|---|---|---|---|
| S0.1 | `node scripts/spike-sqlite.mjs`（Electron 下开库冒烟） | 输出 `SPIKE=PASS` | 失败 → 切 `better-sqlite3`，方案其余不变（记录 ABI 重编译步骤） |
| S0.2 | `node scripts/regression.mjs` | 41 套全绿 | 不绿 → 不得进入迁移 |
| S0.3 | 通知停服窗口（钉钉群） | 群里回执 | — |

### S1 · 停服与备份（约 1 分钟）

| 步骤 | 命令 | 验收点 |
|---|---|---|
| S1.1 | 关闭 DSH 桌面端（插件进程退出） | `Get-Process 'DeepSeek Harness'` 无主进程 |
| S1.2 | `node scripts/migrate-sqlite.mjs --backup-only` | 生成 `data/.json-backup-<ts>/`，文件数 = 原 JSON 数 |
| S1.3 | 记录备份目录路径到迁移报告 | 报告含路径与时间戳 |

### S2 · 建库（约 5 秒）

| 步骤 | 命令 | 验收点 |
|---|---|---|
| S2.1 | `node scripts/migrate-sqlite.mjs --init` | 生成 `data/zeyuan.db` + `-wal`；`schema_migrations` 有 1 行 |
| S2.2 | 校验 PRAGMA | `journal_mode=wal`、`foreign_keys=1`、`busy_timeout=3000` |

### S3 · 导入数据（约 10 秒）

| 步骤 | 命令 | 验收点 |
|---|---|---|
| S3.1 | `node scripts/migrate-sqlite.mjs --apply` | 逐表打印 `导入 N 行`，退出码 0 |
| S3.2 | 引用完整性 | 评论→帖子、分片→上传会话 外键无孤儿（查询返回 0 行） |

### S4 · 一致性校验（关键门禁，约 30 秒）

| 校验 | 通过标准 |
|---|---|
| 行数比对 | 每表行数 = 对应 JSON 数组长度 |
| 主键集合 | 双向差集为空（JSON id 集合 == DB id 集合） |
| 字段抽样 | 每表随机 3 条，关键字段（title/body/status/author/createdAt）逐字相等 |
| 聚合校验 | `SUM(wallet.ledger.delta)` == `SUM(wallet.balances)`（若 wallet 纳入） |
| 脚本产出 | `migration-report.json`，`ok: true` |

> **任一不通过 → 立即进入第 3 节回滚，不得启动服务。**

### S5 · 启动与冒烟（约 2 分钟）

| 步骤 | 验收点 |
|---|---|
| S5.1 启动 DSH | 11 板块全部 `mounted`（mount-events 最新 7 插件 + 新板块） |
| S5.2 `/zeyuan/console/health` | `ok:true`，`reconcile.ok:true` |
| S5.3 三板块读操作 | tasks 列表 8 条 / community 帖子 2 条 / exchange 列表含 1 条 |

### S6 · 写操作回归（约 3 分钟）

| 板块 | 动作 | 验收 |
|---|---|---|
| tasks | 新建 1 条测试任务 → 领取 → 验收 | 状态流转正确；赏金事件发出 |
| community | 发 1 帖 → 1 评论 → P6 隐藏 | 列表/可见性正确 |
| exchange | 上传 1 个小文件 → 下载 sha 一致 → 删除 | sha 相等；删除后 list 不含 |

### S7 · 观察与收尾

## 3. 回滚方案

### 3.1 触发条件（任一命中即回滚，不讨论）

| # | 条件 |
|---|---|
| 1 | S4 任一校验不通过 |
| 2 | 启动后任一块板 `mounted` 失败 |
| 3 | `/health` 非 ok 或对账不平 |
| 4 | S6 写操作出现数据错乱（重复/丢失/状态非法） |
| 5 | 24h 观察期内出现 2 次以上写入失败 |

### 3.2 回滚动作（目标 RTO ≤8 分钟）

```powershell
# 1) 停服
# 2) 删除库（含 WAL/SHM）
Remove-Item "$env:LOCALAPPDATA\zeyuan\data\zeyuan.db*" -Force
# 3) 恢复 JSON 备份（原文件全程未删，此步为兜底覆盖）
Copy-Item "$env:LOCALAPPDATA\zeyuan\data\.json-backup-<ts>\*" "$env:LOCALAPPDATA\zeyuan\data\" -Force
# 4) 回退插件版本（包内保留 v0.4.0 安装包）
# 5) 启动 → 跑 41 套回归 + 三板块读操作
```

| 指标 | 目标 |
|---|---|
| RTO（恢复时间） | ≤8 分钟 |
| RPO（数据丢失） | **0**（JSON 未被删除，DB 期间的写入按第 3.3 处理） |

### 3.3 DB 期间新增数据的处理（回滚时必答）

- 若迁移后已有新写入，回滚会丢失这部分 → **回滚前先导出**：
  `node scripts/migrate-sqlite.mjs --export-json`（DB → JSON，写回 data/）
- 因此回滚标准动作 = **先导出 → 再删库 → 再校验**，避免"回滚即丢数"。

### 3.4 回滚演练（强制）

| 项 | 要求 |
|---|---|
| 时间 | 11-03（SQLite 排期内的演练日） |
| 内容 | 备份 → 迁移 → 校验 → 删库 → 恢复 → 再校验，全流程实际执行 |
| 记录 | 演练耗时、失败点、修复项，写入 `交付/` 演练记录 |
| 门禁 | **未演练不得上线** |

### 4.3 真机对账清单（每板块 ≥15 项，摘要）

| 板块 | 必验动作 |
|---|---|
| tasks | 发布→领取→提交→验收（赏金事件）→驳回→再领取；列表筛选/分页 |
| community | 发帖→评论→P6 隐藏→作者软删→删帖级联；评论可见性 |
| exchange | 上传→列表→下载 sha 一致→删除→分片续传（含 200MB）→sweep 过期 |
| 全局 | 重启后数据仍在；`/health` 对账 ok；审计日志可查 |

### 4.4 "通过"的判定口径（防自欺）

1. **不认"测试跑了"，只认"断言过了"**：每套输出 `通过 N 项，失败 0 项`；
2. **不认"看起来对"，只认"差分相等"**：JSON 版与 DB 版同输入同输出；
3. **不认"能启动"，只认"写操作可回读"**：写后立刻读，字段级比对；
4. **不认"迁移成功"，只认"校验 0 差异"**：S4 报告 `ok:true`；
5. 任何一条不满足 → 回滚，不做"先上线再观察"。

## 5. D-006 共享 store 的归属（本方案明确）

| 项 | 结论 |
|---|---|
| **归属** | **D-006 随 3.7 操作中心立项解决**，由该战役负责人承接 |
| 本方案的角色 | **只是前置依赖声明者**，不实现共享包、不改 7 份 `store.ts` 的组织方式 |
| 本方案的边界 | 仅在**接口边界**上预留：迁移后的 DAO 必须可被未来 `packages/zeyuan-store` 直接包住，**不扩散新副本**（现有 7 份保持不增） |
| 对 3.7 的交付承诺 | 提供《DAO 接口契约草案》（方法签名 + 语义），供 3.7 收敛时零改动接入 |
| 风险 | 若 3.7 不落地，迁移后仍存在 7 份副本（但每份只改"读写实现"，不再复制新逻辑） |

> 一句话：**本方案不碰 D-006 的所有权，只保证不给它添乱。**
