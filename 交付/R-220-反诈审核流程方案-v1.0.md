## 1. 流程闭环（第二条验收）

### 1.1 全景

```
内容产生（接发区）
   │  ① 写入前预审（同步，<20ms）
   ▼
机审引擎（词库 + 规则 + 评分）
   │
   ├─ pass ──▶ 放行（写 scan 记录，不打扰用户）
   ├─ queue ─▶ 入人工队列（内容可见，待复核）
   └─ flag ──▶ 入人工队列 + 内容置“待审”可见性（不直接删）
                    │  ② P6+ 认领（10 分钟锁）
                    ▼
              人工复审（看证据包：命中词/规则/上下文）
                    │  ③ 判定（pass / hide / remove / warn / escalate）
                    ▼
              处置联动（community hide / tasks reject）
                    │  ④ 写审计（11 字段）
                    ▼
              审计可查 + 钉钉通知 + 误报回收进词库
```

### 1.2 谁审（角色与权责）

| 角色 | 档位 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 机审引擎 | 系统 | pass / 入队 / 标记待审 | 不自动删除、不自动封禁 |
| 值班审核员 | **P6** | 认领队列、通过、隐藏内容、驳回任务、警示 | 不能改词库、不能封禁 |
| 审核组长 | **P7** | + 改词库、发布词库版本、复核 P6 的 hide | 不能 escalate 封禁建议 |
| 总师 | **P8** | + escalate 处置（封禁建议）、开关影子模式、紧急降级 | — |
| 普通学员 | LV1 | 只可举报（新增入口） | 不进队列、不处置 |

**值班制**：工作时间 P6 值班（认领 ≤15 分钟）；非工作时段由 P7/P8 兜底；无人认领超 30 分钟 → 钉钉提醒（复用 im）。

### 1.3 审什么（内容面与字段）

| 来源 | 审的字段 | 触发时机 |
|---|---|---|
| tasks 发布任务 | `title`、`description` | create 时 |
| tasks 提交成果 | `submitNote`（提交说明） | submit 时 |
| community 发帖 | `title`、`body` | draft→publish 时 |
| community 评论 | `body` | add 时 |
| collab 建组 | `name`、`topic` | create 时 |
| exchange 上传 | `name`（文件名） | upload 时 |
| 用户举报 | 举报理由 + 被举报对象 | 举报时（**新增**，优先级最高） |

**不审**：私聊、钱包流水、审计日志、license、任何二进制内容。

### 1.4 拦截规则（分级）

规则分三层，**按"证据强度"而非"词面恶意"定级**：

| 层 | 规则类型 | 示例（脱敏） | 默认动作 |
|---|---|---|---|
| R1 | 高危组合（涉诈词 + 联系方式 + 转账动作） | "刷单"+"vx:"+"先垫付" | **flag**（入队 + 待审） |
| R2 | 单类强特征（明确诈骗话术） | "杀猪盘"、"稳赚不赔"、"内部渠道" | **flag** |
| R3 | 弱信号（单关键词、热点词） | "返利"、"兼职" | **queue（仅记录，不改变可见性）** |

**硬性规则**：
- 任何规则都**不允许自动删除**内容；最高动作是"标记待审（待审可见性）"；
- 命中 R1/R2 必须**给出可解释证据**（命中词 + 规则 id + 上下文片段），否则不得入队；
- 白名单优先：官方反诈科普模板不触发（避免"教人防骗"被判诈骗）。

### 1.5 违规判定标准（人工判定用）

| 判定 | 定义 | 证据要求 | 处置 |
|---|---|---|---|
| **确属违规-引流诈骗** | 存在明确的诈骗引流意图（联系方式 + 收益承诺 + 转账/垫付要求） | ≥2 条独立证据 | hide + 记违规 + 通知作者 |
| **确属违规-虚假承诺** | 明示"稳赚/保本/内部名额"等不可实现承诺 | 1 条明确证据 | hide |
| **违规-骚扰/黑产** | 批量重复、机器刷屏、外链导流 | 行为证据（频次/重复） | hide + 建议封禁（escalate，P8 决定） |
| **不违规-误报** | 命中词但语境正常（科普、新闻转述、讨论） | 语境说明 | pass + 词条误报 +1 |
| **存疑** | 证据不足 | 记录疑点 | **留队（不放行也不处置）**，24h 内升级 P7 |

**判定原则**：
1. **看意图不看词**：词只是线索，判定必须落到"意图 + 证据"；
2. **疑罪从无**：证据不足 → 存疑留队，不处置；
3. **同类同判**：同一周内同类内容判定必须一致，不一致需组长复核（口径一致要求）；
4. **留痕**：每次判定必写 reason（≥4 字）+ 证据快照。

### 1.6 闭环回写

| 环节 | 回写 |
|---|---|
| 判定结果 | 写审计（actor/tier/action/target/before/after/result/reason） |
| 误报 | 词条 `misfire+1`，连续 5 次 → 词条转 draft 待复核 |
| 违规 | 作者违规计数 +1；达阈值（如 3 次/30 天）→ 建议 escalate（P8） |
| 通知 | hide/remove/escalate → 钉钉通知（复用 im） |
| 统计 | 待审数/平均处理时长/误报率/TOP 命中词 → 控制台 |

| 表 | 用途 |
|---|---|

## 3. 拿不准清单（交总控裁定，不自行写死）

| # | 拿不准的点 | 两种可选口径 | 我为什么不敢定 | 不定时的临时处理 |
|---|---|---|---|---|
| 1 | **"待审可见性"**怎么表现 | A 对他人隐藏、作者可见；B 全站可见但打"审核中"标 | 影响用户体验与合规表述，属产品口径 | 按 A 实现，开关可切 |
| 2 | R1 高危组合是否允许**自动置待审** | A 允许（非删除）；B 一律人工后才改可见性 | 关系到"机审权力边界" | 按 A，但默认关闭（影子期） |
| 3 | **违规计数阈值**与后果 | A 3 次/30 天 → 建议封禁；B 5 次/90 天 | 属处罚政策，不是技术参数 | 按 A，仅"建议"，P8 决定 |
| 4 | 存疑件**最长留队时长** | A 24h 升级 P7；B 48h | 影响积压与漏判平衡 | 按 A |
| 5 | 被审文本**留存期** | A 90 天；B 180 天；C 只存命中片段 | 隐私/合规口径 | 按 A，可配置 |
| 6 | 是否允许**第三方机审 API** | A 不接；B 脱敏后接 | 隐私外发需法务口径 | 按 A（不接） |
| 7 | **举报入口**放哪 | A 帖子/评论菜单；B 单独举报页 | 交互口径 | 按 A |
| 8 | 词库是否**对外公开** | A 不公开（防规避）；B 部分公开（透明） | 反规避 vs 透明治理 | 按 A |
| 9 | 与**im 通知**的边界 | A 全部处置都通知；B 仅 hide/remove/escalate | 打扰程度 | 按 B |
| 10 | 影子模式**默认时长** | A 7 天；B 3 天 | 与上线窗口相关 | 按 A |

> 以上 10 项**我不拍脑袋**：方案里给的"临时处理"仅为可运行默认值，**总控裁定后以裁定为准**，我改方案与实现。
