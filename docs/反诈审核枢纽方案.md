## 2. 目标 / 非目标

### 目标

1. **三级词库**：反诈基础词、涉诈话术、热点词（带 TTL），版本化、可灰度、可回溯；
2. **机审预审**：规则引擎（关键词 / 正则 / 组合规则 / 评分），输出 `pass | queue | block` + **可解释命中项**；
3. **人工复审工作流**：队列 → 认领（防撞单）→ 复核 → 处置 → 留痕，带 SLA；
4. **处置联动**：隐藏内容 / 驳回任务 / 记审计 / 钉钉通知，全部走既有能力；
5. **控制台可见**：队列与处置统计进 console 仪表盘；每次处置写 `audit-log`。

### 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 替代公安/平台举报流程 | 定位是**站内预审 + 人审**，不承担执法职能 |
| 自动封号/自动扣币 | 封禁与财产处置仍需 P7+/P8 人工确认（避免误伤） |
| 采集手机号/身份证等敏感信息 | 只审**已发布内容文本**，不新增采集面 |
| 把内容外发第三方机审 SaaS | 隐私与合规风险；如确需，走决策 4 |
| 图片/视频内容审核 | 本版只做文本（exchange 只审文件名） |

## 3. 总体架构

```
内容写入（community/tasks/collab/exchange）
        │  （同步钩子，<20ms 预算）
        ▼
  ┌──────────────┐   命中    ┌───────────────┐   P6+ 认领   ┌──────────────┐
  │ 机审预审引擎  │ ────────▶ │ 人工复审队列   │ ──────────▶ │ 处置与联动    │
  │ rules+lexicon│           │ review_queue  │             │ hide/reject/ │
  └──────────────┘           └───────────────┘             │ audit/im     │
        │ pass                       │ 驳回/通过              └──────────────┘
        ▼                            ▼
   直接放行（留 scan 记录）      结论回写 + 词库质量回收
```

**关键设计**：机审**不阻塞**写入路径超过 20ms；命中即写 scan 记录并入队，内容按策略处理（决策 1）。

## 4. 词库设计

### 4.1 三层结构

| 层 | 名称 | 示例（脱敏示意） | 作用 | 默认动作 |
|---|---|---|---|---|
| L1 | 反诈基础词 | 刷单、返利、杀猪盘、虚拟币投资、内部渠道 | 识别高风险语义 | 计分 |
| L2 | 涉诈话术 | "稳赚不赔"、"导师带你"、"先垫付后返还" | 组合触发 | 计分 + 组合规则 |
| L3 | 热点词（TTL） | 近期高发骗局关键词（如某平台名 + 转账） | 短期加权 | **只加权不阻断** |

### 4.2 词条字段

```jsonc
{
  "id": "kw-0001",
  "term": "刷单",
  "layer": "L1",              // L1 | L2 | L3
  "weight": 60,               // 0-100
  "match": "substring",       // substring | regex | word
  "variants": ["刷单返利", "刷单兼职"],   // 变形/同义
  "note": "常见引流话术",
  "source": "自建|案件复盘|公开通报",     // 来源可追溯
  "status": "draft|active|retired",
  "version": 3,
  "updatedBy": "TxzF2",
  "updatedAt": "2026-11-01T…"
}
```

### 4.3 治理规则

1. **变更需 P7+**，每次变更写审计；发布用 `version` 递增，可回滚到上一版；
2. **灰度**：新词先 `draft`，在影子模式跑 7 天（只记录不处置），看误报再 `active`；
3. **质量回收**：人工复审"误报"自动给词条 +1 误报计数，连续误报 ≥5 → 自动转 `draft` 待复核；
4. **热点词 TTL**：默认 14 天自动 `retired`（可续期），避免长期误伤。

## 5. 机审引擎

### 5.1 规则类型

| 类型 | 说明 | 例 |
|---|---|---|
| 关键词命中 | 词库加权求和 | 命中 L1×2 + L2×1 = 60+40=100 |
| 组合规则 | 多条件同时满足才触发 | 涉诈词 + 联系方式（微信号/QQ/手机号正则）+ 转账动词 |
| 正则规则 | 高精度模式 | `(?:\+?86)?1[3-9]\d{9}`、`v[x]?[:：]\s*\w+` |
| 白名单 | 反向豁免 | 官方反诈宣传话术模板（避免把科普当诈骗） |

### 5.2 判定阈值（可配置）

| 分值 | 判定 | 处置 |
|---|---|---|
| 0–39 | `pass` | 放行，留 scan 记录 |
| 40–79 | `queue` | 入人工复审队列，内容保持可见（或按决策 1 处理） |
| ≥80 或组合规则命中 | `block` | 立即隐藏（`hiddenBy=guard`）+ 入队，人工可推翻 |

### 5.3 可解释性（强制）

每条 scan 结果必须含：

```jsonc
{
  "hitTerms": [{"term":"刷单","weight":60,"layer":"L1"}],
  "hitRules": [{"id":"combo-contact-money","score":40,"detail":"命中联系方式+转账动词"}],
  "score": 100,
  "verdict": "block",
  "whitelisted": false
}
```
> 人审看不到"为什么"就等于黑箱，方案把可解释性列为门槛项。

## 6. 人工复审工作流

### 6.1 状态机

```
queued ──claim(P6+)──▶ reviewing ──decide──▶ decided
   ▲                     │ 超时 10min 自动释放（防占坑）
   └──── 重新入队 ◀──────┘
```

### 6.2 处置选项

| 决定 | 联动动作 | 需二次确认 |
|---|---|---|
| `pass`（误报） | 内容保持/恢复；词条误报 +1 | 否 |
| `hide` | 调 community hide / tasks reject | 是（理由 ≥4 字） |
| `remove`（软删） | 作者软删语义 | 是 |
| `warn` | 记警示 + 钉钉通知作者（可选） | 否 |
| `escalate` | 升级 P8 处理（封禁建议） | 是 |

### 6.3 SLA 与统计

- 队列目标：P6 认领 ≤15 分钟，处置 ≤30 分钟（工作时间）；
- 控制台展示：待审数、平均处理时长、误报率、命中 TOP 词；
- 超时未处理 → 钉钉群提醒（复用 im）。

## 7. 数据模型（建议入 SQLite，与 W2 对齐）

```sql
CREATE TABLE guard_terms (
  id TEXT PRIMARY KEY, term TEXT NOT NULL, layer TEXT NOT NULL,
  weight INTEGER NOT NULL, match TEXT NOT NULL DEFAULT 'substring',
  variants TEXT NOT NULL DEFAULT '[]', note TEXT, source TEXT,
  status TEXT NOT NULL DEFAULT 'draft', version INTEGER NOT NULL DEFAULT 1,
  misfire INTEGER NOT NULL DEFAULT 0,
  updated_by TEXT, updated_at TEXT NOT NULL
);
CREATE INDEX idx_terms_status ON guard_terms(status, layer);

CREATE TABLE guard_rules (
  id TEXT PRIMARY KEY, kind TEXT NOT NULL,       -- combo | regex
  expr TEXT NOT NULL, score INTEGER NOT NULL, enabled INTEGER NOT NULL DEFAULT 1,
  note TEXT, updated_at TEXT NOT NULL
);

CREATE TABLE guard_scans (
  id TEXT PRIMARY KEY, subject TEXT NOT NULL,    -- post|comment|task|collab|file
  subject_id TEXT NOT NULL, author TEXT,
  text TEXT NOT NULL,                            -- 仅存被审文本（留存期见决策 3）
  score INTEGER NOT NULL, verdict TEXT NOT NULL,
  hits TEXT NOT NULL,                            -- 可解释 JSON
  created_at TEXT NOT NULL
);
CREATE INDEX idx_scans_created ON guard_scans(created_at);

CREATE TABLE guard_queue (
  id TEXT PRIMARY KEY, scan_id TEXT NOT NULL REFERENCES guard_scans(id),
  status TEXT NOT NULL DEFAULT 'queued',         -- queued|reviewing|decided
  claimed_by TEXT, claimed_at TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_queue_status ON guard_queue(status, created_at);

CREATE TABLE guard_decisions (
  id TEXT PRIMARY KEY, queue_id TEXT NOT NULL REFERENCES guard_queue(id),
  reviewer TEXT NOT NULL, reviewer_tier INTEGER NOT NULL,
  decision TEXT NOT NULL, reason TEXT NOT NULL,
  actions TEXT NOT NULL,                         -- 联动结果 JSON
  created_at TEXT NOT NULL
);
```

> 若决策 6 选择"先 JSON"，则表结构不变，改用现有 `store.ts` 接口，SQLite 迁移后透明切换。

## 12. 风险与对策
