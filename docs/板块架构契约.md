# 《板块架构契约 v2》

| 项 | 内容 |
|---|---|
| 契约版本 | `schemaVersion: 2` · `boardApi: 1` |
| 校验器 | `packaging/scripts/check-boards.mjs`（手写校验，不引第三方依赖） |
| schema | `packaging/contracts/board.schema.json`（文档用，校验逻辑以校验器为准） |
| 适用范围 | `packaging/boards/<id>/` 下全部板块 |

---

## 1. 一句话

**板块 = 一份可校验的清单 + 一份可跑通的 smoke + 一组声明过的事件 + 一个确定的落点。**
四样缺一，就不允许 `status: ready`。

## 2. `board.json` 字段

| 字段 | 必填 | 规则 |
|---|---|---|
| `id` | ✅ | `^[a-z][a-z0-9-]*$`，与目录名一致 |
| `schemaVersion` | ✅ | 固定 `2` |
| `boardApi` | ✅ | 固定 `1`；**整数、只兼容相等**——`boardApi 1` 的板块只能被 `boardApi 1` 的宿主加载 |
| `displayName` | ✅ | 中文名 |
| `kind` | ✅ | `required` / `optional` / `preview` |
| `status` | ✅ | `skeleton` / `placeholder` / `ready` |
| `version` | ✅ | semver |
| `dependsOn` | ✅ | 板块 id 数组 |
| `defaultSelected` | ✅ | 布尔 |
| `install` | ✅ | `{ target, mode }`，见 §3 |
| `contents` | ✅ | 人读清单 |
| `assetManifest` | ➖ | 有资产时必填 |
| **`smoke`** | ✅ | `test-<id>.mjs` |
| **`events`** | ✅ | `{ emits, consumes }`，见《事件总线规范》 |
| `capabilities` | ➖ | 与 License scope 对齐 |
| `sizeBytes` | ➖ | 构建回填，不手写 |

## 3. 装配落点（`install`）

| kind | target | mode |
|---|---|---|
| `required`（core） | 由 profile `wire()` 写入（不落 app 目录） | `plugin-link` |
| `character-*` | `assets/characters/<name>` | `asset-copy`（插件本体统一进 `app/plugins/<name>`） |
| `theme-*` | `assets/themes/<name>` | `asset-copy` |
| `feature-*` / `tasks` | `features/<name>` | `copy` |

- 安装器按 `board.json` 的 `install.target` 计算落盘路径（`packaging/installer/shell/main.js` 的 `buildPayload()`）；
- 所有落盘文件写入装机清单 `files[]`；**卸载只删清单内文件**，再剪空目录 → 可逆；
- 反例：`required` 板块写成 `asset-copy`、`feature-*` 写成 `plugin-link`，校验器直接报错。

## 4. 依赖规则

1. `required` 恰好 1 个，且不得有依赖；
2. `dependsOn` 必须存在、禁止自依赖、禁止成环（DFS 检测）；
3. `preview` 板块不得被 `required` 依赖；
4. 层级顺序：`required` > `optional` > `preview`（低层不能要求高层，`core` 除外）。

## 5. Smoke 硬契约

> **没有 smoke 的板块，不允许 `status: ready`。** 这不是建议，是构建闸门。

| 要求 | 说明 |
|---|---|
| 文件 | `packaging/boards/<id>/test-<id>.mjs` |
| 框架 | `packaging/scripts/board-smoke-lib.mjs`（统一 5 类断言、统一输出格式） |
| 断言 1 | 清单合法性（id/枚举/字段/install/smoke 命名） |
| 断言 2 | 资产完整性（每个文件存在、数量与字节对得上；`ready` 板块要求 manifest `status=done`） |
| 断言 3 | 事件一致性（emits 属于本板块且命中注册表；consumes 是注册表内事件） |
| 断言 4 | 依赖满足（存在、不自依赖） |
| 断言 5 | 装配/卸载可逆（复制 → 校验 → 删除 → 残留 0） |
| 输出 | `通过 N 项，失败 M 项`，退出码 0/1 |

**执行位置**

| 环节 | 行为 |
|---|---|
| `node packaging/scripts/check-boards.mjs` | 只跑 `ready` 板块的 smoke |
| `node packaging/scripts/check-boards.mjs --all` | 跑全部板块 smoke |
| `node packaging/scripts/build.mjs --stage 2` | **出包前强制**跑一次 check-boards，失败即拒绝出包 |
| `node scripts/regression.mjs` | 一键全量：13 套（含全部板块 smoke） |

## 7. 迁移指南（v1 → v2）

```jsonc
// 新增/必填
"schemaVersion": 2,
"boardApi": 1,
"version": "0.1.0",
"smoke": "test-<id>.mjs",
"events": { "emits": [], "consumes": [] },
"install": { "target": "features/xxx", "mode": "copy" }
```

1. 跑 `node packaging/scripts/check-boards.mjs --all` 看报错；
2. 补齐字段 → 写 `test-<id>.mjs`（三行调用基座）；
3. 在 `packaging/contracts/events.json` 登记本板块事件；
4. 全绿后才允许把 `status` 提到 `ready`。
