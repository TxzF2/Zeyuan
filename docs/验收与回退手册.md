## 4. 三组故障注入结果（核心证据）

> 注入手段全部在 `lib/installer.js` 的 `faults` 参数上，**不改产品代码**；
> 每组还额外核验「失败之后旧版本是否还活着」。

### 4.1 写盘失败（E-201）

| 项 | 内容 |
|---|---|
| 注入方式 | `faults.failWriteAt = 1`（第 2 个文件写入时抛 `EACCES`） |
| 预期 | 报 `E-201` + 中文文案；`app/` 不产生；`.staging` 被清空 |
| 实测错误码 | **E-201** |
| 实测文案 | 「装配写盘失败：resources/app.js（目标目录没有写入权限）」 |
| 回退后状态 | `app/` 不存在 ✅；`.staging/*` 为 0 个 ✅；未产生备份 ✅ |
| 结论 | **PASS** —— 失败不留半成品 |

### 4.2 哈希不符（E-205）

| 项 | 内容 |
|---|---|
| 注入方式 | `faults.corruptFile = 'index.html'`（升级场景：已装 v1，尝试装 v2 时校验失败） |
| 预期 | 报 `E-205`；**旧版本内容与清单毫发无损**；不产生备份 |
| 实测错误码 | **E-205** |
| 实测文案 | 「校验失败：index.html 的哈希与安装包不一致（文件可能在传输中损坏）。」 |
| 回退后状态 | 旧版 `index.html` 内容未变 ✅；旧版 `install-manifest.json` 仍在 ✅；`.backup` 未新增 ✅ |
| 结论 | **PASS** —— 校验失败发生在备份**之前**，旧版本连动都没动 |

### 4.3 中途取消（E-206，两个时点）

| 时点 | 注入 | 预期 | 实测 |
|---|---|---|---|
| 装配后取消 | `faults.cancelAt = 'after-stage'` | `E-206`；无半成品；staging 清理 | ✅ 文案「已取消安装，临时文件已清理。」；`app` 不存在；staging 0 |
| 备份后取消 | `faults.cancelAt = 'after-backup'` | `E-206`；**旧版本被恢复** | ✅ 文案「已取消安装，已恢复原版本。」；旧版内容回到 0.1.0；`.backup` 已移回、无遗留 |

**为什么专挑"备份后取消"**：这是最容易留下"安装目录空着、旧版本躺在 backup 里"的窗口期。
本实现用 `catch` 里的「已备份但未替换 → 把备份移回」兜住了这一格。结论：**PASS**。

安装器把核心板块接进 DSH profile，属于**安装目录之外**的副作用，因此单独做了事务化处理。

| 用例 | 注入/条件 | 期望 | 实测 |
|---|---|---|---|
| 首次接入 | 空 profile | 写 `dependencies` + `bundles`，产生备份 | ✅ `changed:true`，备份 `package.json.bak-*` |
| 重复接入 | 已是目标状态 | 幂等，文件字节不变 | ✅ `changed:false` |
| 覆盖旧路径 | 已有旧 `link:` | 覆盖为新路径，不重复追加 | ✅ |
| JSON 损坏 | 手工破坏 JSON | `E-502`，**原文件不被改写** | ✅ 原文逐字节保留 |

| 安装中途失败 | profile 损坏 + 正常载荷 | 安装**整体回滚**，`app/` 不残留 | ✅ `E-502` + `app` 不存在 |

## 5. 目录语义（支持人员必读）

```
%LOCALAPPDATA%\dsh-training\
├─ app\                当前生效版本（回滚的原子替换目标）
│  └─ install-manifest.json   ★ 装机清单：版本/板块/逐文件 sha256
├─ .staging\<ts>\      装配中；正常情况下**应为空**
├─ .backup\<ts>\       上一版本；回滚的恢复源
├─ .failed\<ts>\       回滚时踢出的坏版本（留证，别急着删）
└─ last-install.json   最近一次操作：install/rollback + 结果码
```

判定规则：

| 现象 | 含义 |
|---|---|
| `.staging` 里有目录残留 | 曾发生异常中断；可安全删除，删前先看 `last-install.json` |
| `.backup` 有多份 | 多次升级未清理；保留最新一份即可 |
| `app` 不存在但 `.backup` 有 | 上次替换失败；执行"回滚"或手动把 backup 移回 app |

## 6. A1–A6 验收对照

| 编号 | 标准（摘自构建说明第 7 节） | 验收方法 | 结论 | 证据 | 缺口 |

## 8. 回退操作手册（人工处置）

### 8.1 装坏了想退回上一版

1. 打开向导 → 第 4 步「**回滚到上一版本**」（有备份才可点，灰的就是没备份）；
2. 命令行兜底（支持人员用）：
   ```powershell
   # 把当前版本踢到 .failed，把最近备份移回 app
   $t = "$env:LOCALAPPDATA\dsh-training"
   Get-Content "$t\last-install.json"      # 先看上次干了什么
   ```
3. 回滚后确认 `app\install-manifest.json` 里的 `version` 是期望版本。

### 8.2 想彻底重来

```powershell
# 1) 先卸载（走清单，安全）
#    向导里没有卸载入口时，手动删整个容器目录也可（数据不在里面）
Remove-Item "$env:LOCALAPPDATA\dsh-training" -Recurse -Force
```

### 8.3 保留现场（报障前）

```powershell
$t = "$env:LOCALAPPDATA\dsh-training"
Copy-Item "$t\last-install.json" "$env:TEMP\dsh-failure-last-install.json"
Get-ChildItem "$t\.failed" -Recurse | Select-Object FullName   # 坏版本留证
```

**不要**在报障前删 `.failed` / `.backup`：那是唯一的现场证据。
