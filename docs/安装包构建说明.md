## 1. 选型结论

**选定：B · Electron 壳 + 内嵌 DSH Web（内置运行时），分三阶段落地。**

| 维度 | A. fork 社区发行版 | **B. Electron 壳（选定）** | C. 纯引导脚本包 |
|---|---|---|---|
| 零命令行暴露 | 基本满足，向导不归我们 | ✅ 全自控 | ❌ 本质就是让用户开终端 |
| 板块可选装 | ❌ 装的是整包 exe | ✅ 勾选 → 写 profile `bundles` | ⚠️ 要用户自己跑脚本 |
| 品牌可控度 | 有限 | ✅ 全部可控 | ✅ 但只有文字 |
| 长期维护负担 | ❌ 绑死上游节奏 | ⚠️ 中（本体升级解耦） | ✅ 低 |
| 上手速度 | ✅ 最快 | ❌ 最慢 | ✅ 快 |

**并入 B 的两点**：
1. 借用 A 的「内置运行时、开箱即用」——便携版自带 Node，学员无需装 Node；
2. C 不作为交付形态，只作为**打包机的构建期脚本**（本目录的 `scripts/`），并承担「不静默安装系统级组件」这条约束。

## 2. 目录结构

```
packaging/
├─ distribution.json          # 发行元数据：版本/渠道/日期/目标平台/内置运行时（版本唯一来源）
├─ boards.json                # 板块唯一事实源：id/显示名/类型/依赖/默认勾选/状态
├─ boards/
│  ├─ core/                   # 必装：DSH 运行时 + dsh-training-protocol
│  ├─ character-txzf/         # 可选：星辰（TxzF）资源包 + asset-manifest.json
│  ├─ character-changzhengji/ # 可选：长征姬资源包 + asset-manifest.json
│  ├─ theme-xingchen/         # 可选：星辰主题色板 + asset-manifest.json
│  └─ feature-*/              # 功能预览 5 个（taskboard/workbench/community/console/collab）
├─ runtime/
│  ├─ node-requirements.json  # 最低 22.19.0；缺失时「只提示不安装」的处置清单
│  └─ detect-node.mjs         # 只读检测脚本，人读 + `--json` 两种输出
├─ installer/
│  ├─ shell/                  # Electron 壳（main.js / preload.js / package.json），最小可运行
│  └─ wizard/                 # 向导页骨架（欢迎→环境→板块→安装→完成+LV0 协议）
├─ scripts/
│  ├─ version.mjs             # 版本 bump 与产物文件名唯一实现
│  ├─ build.mjs               # 构建入口（阶段一=干跑校验，拒绝出包）
│  ├─ verify.mjs              # 产物文件名合规 + SHA256 清单
│  └─ scaffold-boards.mjs     # 按 boards.json 补齐板块目录（幂等）
└─ artifacts/                 # 产物输出目录（git 忽略）
```

## 3. 打包机环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 1809+ / Windows 11（x64） |
| Node.js | **≥ 22.19.0**（与 DSH 运行时要求一致） |
| pnpm | 12.x（用于装配插件依赖） |
| Git | 任意近期版本（产物留 commit 号） |
| 磁盘 | ≥ 2 GB 空闲（阶段二便携版含内置运行时约 300–500 MB） |
| 签名证书 | 阶段三才需要（阶段一/二不签名，见第 11 节 SmartScreen） |

> 打包机**不允许**把 Node/依赖装进系统目录以外的位置写死；所有路径一律相对 `packaging/` 解析。

## 4. 改版本：五步流程（禁止手改文件名）

```powershell
cd C:\Users\29496\.dsh\plugin-sources\dsh-training

# 步骤 1 · 提升版本（唯一入口，自动改写 distribution.json 的 version 与 buildDate）
node packaging/scripts/version.mjs --bump patch     # 0.1.0 → 0.1.1
# 预发布：node packaging/scripts/version.mjs --pre beta   # → 0.1.1-beta.1（再跑自增）

# 步骤 2 · 确认板块清单（有新增板块时先跑 scaffold）
node packaging/scripts/scaffold-boards.mjs

# 步骤 3 · 干跑校验（阶段一永远是这一步；阶段二起才真正出包）
node packaging/scripts/build.mjs

# 步骤 4 · 出包（阶段二实现后）
node packaging/scripts/build.mjs --stage 2

# 步骤 5 · 校验产物 + 生成哈希清单
node packaging/scripts/verify.mjs
```

**版本规则**

- 语义化版本，**从 `v0.1.0` 起**；预发布 `-alpha.N` / `-beta.N` / `-rc.N`。
- 文件名规则（由 `distribution.json` 的 `filePattern` 定义）：
  `dsh-training-<形态>-v<版本>-<YYYYMMDD>-<arch>.<ext>`
  - `dsh-training-portable-v0.2.0-20261022-x64.zip`（阶段二）
  - `dsh-training-setup-v0.2.0-20261022-x64.exe`（阶段三）
  - `dsh-training-board-v0.2.0-20261022-x64.zip`（单板块增量包）
- `buildDate` 由 `version.mjs` 按当天日期覆写，**不要手工维护**。

## 5. 打包流程（按阶段）

### 阶段一（当前）
```powershell
node packaging/scripts/build.mjs        # 只校验 + 打印产物计划，退出码 0
```
`build.mjs --stage 2|3` 会被**明确拒绝**（退出码 3），防止误产出成品。

### 阶段二 · 第 1 步（✅ 已完成：运行环境检测接通）

| 已交付 | 说明 |
|---|---|
| `installer/shell/lib/detect-runtime.js` | 检测核心，**不依赖 Electron**，可被 Node 单测直接跑 |
| `installer/shell/main.js` | 新增 IPC：`detect-node`、`open-external`（域名白名单），保留 `runtime-info` |
| `installer/shell/preload.js` | 暴露 `detectNode()` / `openExternal()` / `capabilities` / `links` |
| `installer/wizard/index.html` | 环境检测状态机：idle→checking→ok/E-101/E-102/error，联动安装按钮与出错面板 |
| `scripts/test-detect-node.mjs` | E-101 / E-102 **真机复现**测试（14 项断言） |
| 自检钩子 | `DSH_TRAINING_SELFTEST=1` 启动时跑通 IPC → 截图 → 写 `artifacts/qa/selftest-report.json` → 退出 |

**E-101 / E-102 如何真机复现（不靠改代码造假）**

| 场景 | 手法 | 为什么这样最真实 |
|---|---|---|
| **E-101** 缺 Node | 把 `PATH` 指向一个空目录后调用检测 | `node` 命令真的不存在，真走 `ENOENT` 分支 |
| **E-102** 版本过低 | 设 `DSH_TRAINING_NODE_MIN=99.0.0`（QA 钩子） | 真机 Node 24.21.0 真的低于门槛，版本比较真的失败，文案带的是真实版本号 |

> 真机是新版 Node，不改门槛永远走不到「版本过低」分支；用环境变量抬高门槛是唯一不改代码的端到端办法。
> 该变量只影响 `detect-runtime.js` 读取的门槛值；生产环境不设置即为 `runtime/node-requirements.json` 的值。

```powershell
# 一键跑三个用例（OK / E-101 / E-102）
node packaging/scripts/test-detect-node.mjs     # 期望：通过 14 项，失败 0 项

# 真实 Electron 里跑 IPC 自检（会闪现窗口约 1 秒）
$env:DSH_TRAINING_SELFTEST = "1"
cd packaging\installer\shell
.\node_modules\electron\dist\electron.exe .
# → artifacts/qa/selftest-report.json（result: PASS）+ artifacts/qa/selftest-wizard.png
```

### 阶段二 · 第 2 步（✅ 已完成：安装线 + 回滚）

| 已交付 | 说明 |
|---|---|
| `installer/shell/lib/installer.js` | 安装线核心（纯 Node）：`runInstall` / `runRollback` / `runUninstall` / `getStatus` |
| 目录布局 | `<target>\app`（当前版本）· `.staging\<ts>` · `.backup\<ts>` · `.failed\<ts>` · `last-install.json` |
| 原子性 | staging 与 app **同盘同卷**，替换走 `rename` 而非跨盘复制 |
| 失败回滚 | 写盘/校验/取消任一失败：清 staging；若已备份则把备份移回；若已替换则踢到 `.failed` 再恢复备份 |
| 装机清单 | `app/install-manifest.json`（版本、板块、逐文件 sha256），**跟着版本一起回滚** |
| IPC | `install`（带 `install-progress` 进度事件）、`rollback`、`uninstall`、`status` |
| 向导 UI | 进度条 + 阶段文案 + 取消提示 + 回滚按钮（无备份时禁用，不假装可点） |
| 测试 | `scripts/test-install-line.mjs`：10 个场景 / **40 项断言**，含三类故障注入 |

**故障注入怎么做的（A2 的实证方式）**

| 注入点 | 参数 | 期望 |
|---|---|---|
| 写盘失败 | `faults.failWriteAt = 1` | `E-201`，`app` 不存在，`staging` 清空 |
| 哈希不符 | `faults.corruptFile = 'index.html'` | `E-205`，**旧版本内容与清单毫发无损** |
| 装配后取消 | `faults.cancelAt = 'after-stage'` | `E-206`，无半成品 |
| 备份后取消 | `faults.cancelAt = 'after-backup'` | `E-206`，**旧版本被恢复** |

```powershell
node packaging/scripts/test-install-line.mjs     # 期望：通过 40 项，失败 0 项

# 真实 Electron 里跑安装线 IPC（目标指到临时目录，别污染真实安装）
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
$env:DSH_TRAINING_SELFTEST="1"; $env:DSH_TRAINING_SELFTEST_INSTALL="1"
$env:DSH_TRAINING_TARGET_DIR="$env:TEMP\dsh-training-selftest"
cd packaging\installer\shell; .\node_modules\electron\dist\electron.exe .   # 期望 RESULT=PASS
```

> **阶段三接续点**：`main.js` 的 `buildPayload()` 换成真实运行时文件清单即可，
> 装配/校验/替换/回滚流程一行不用改。

**设计取舍**：不声明 `inject:['webServer']`，改为"有则注册路由、无则跳过"——
否则裸 Context 的单测与冒烟环境里插件永不 `apply`，A5 的 L2 证据会失效。

**安全边界**：本地对称密钥只能防篡改、不能防伪造；升级路径见 backlog **D-003**。

**真机验证（2026-10-24）**：应用重启后插件以 v0.3.0 挂载；协议路由 200；签署后 LV0→LV1、六项校验全绿（含 HMAC）；吊销回落 LV0；设置内「培训班 · 协议授权」面板存在。

> 踩坑记录：路由最初 404——`apply()` 时 `ctx.webServer` 尚未就绪，"有则注册无则跳过"直接把注册跳过了。
> 正解是 `ctx.inject(['webServer'], cb)` 动态等待；不能改回 `inject:['webServer']` 声明，否则裸 Context 测试永不 apply。

## 6. 错误码表（面向学员的中文报错来源）

| 错误码 | 场景 | 学员看到的中文 | 建议动作 |
|---|---|---|---|
| **E-101** | 未检测到 Node 运行时 | 「本机没有 Node 运行时，本安装包不会自动安装系统组件」 | 打开官方下载页 / 重新检测 / 改用内置运行时便携版 |
| **E-102** | Node 版本过低 | 「当前 Node 20.11.1，低于最低要求 22.19.0」 | 升级 Node 后重试，或换便携版 |
| **E-201** | 安装目录不可写 | 「这个位置没有写入权限」 | 换目录（推荐用户目录）/ 改用便携版 |
| **E-202** | 磁盘空间不足 | 「目标磁盘剩余空间不足，需要约 500 MB」 | 清理或换盘 |
| **E-203** | 文件被占用 | 「有文件正在被使用（可能培训程序还开着）」 | 关闭后重试（提供「结束并继续」按钮） |
| **E-204** | 板块包下载失败 | 「板块包下载失败，可能是网络问题」 | 重试 / 离线包导入 / 换镜像 |
| **E-205** | 哈希校验不符 | 「下载的文件不完整或被修改」 | 重新下载（附镜像地址） |
| **E-206** | 用户取消安装 | 「已取消安装，临时文件已清理」 | 重新点「开始安装」（升级场景会提示已恢复原版本） |
| **E-207** | 装配写盘失败 | 「装配文件时出错」 | 检查磁盘/权限后重试；已自动回滚 |
| **E-208** | 安装包内容为空 | 「安装包内容为空，没有可安装的文件」 | 重新下载（包可能损坏） |
| **E-209** | 没有可回滚的备份 | 「没有可回滚的备份（这是第一次安装）」 | 无需回滚，直接重装 |

## 7. 验收标准（发布前逐条打勾）`n`n> 逐条证据与回退操作见 [《验收与回退手册》](验收与回退手册.md)；发版填表用 [《发版测试报告模板》](发版测试报告模板.md)。

| 编号 | 验收标准 | 验收方法 | 阶段 |
|---|---|---|---|
| **A1** | 安装失败有可读中文报错，且有「重试」入口 | 断网 / 占端口 / 只读目录，各制造一次失败，比对第 6 节错误码 | 二 |
| **A2** | 任何一步失败可回滚 | staging 装配中途杀进程，确认已装版本仍能启动；卸载后无残留（按装机清单核对） | 二 |
| **A3** | 全程零命令行 | 让一位没用过终端的同事照《下载者安装手册》盲操 | 二 |
| **A4** | Node 缺失只提示不安装 | 干净虚拟机（无 Node）实测：向导提示 + 下载页按钮，**系统无任何变化** | 二 |
| **A5** | 板块可选装 | 勾选不同组合安装，对比 profile `dsh.profile.bundles` 差异；阶段三再验增删 | 二/三 |
| **A6** | 首次启动直达 LV0 协议页，未签署不进 LV1 | 走一遍 `canEnterLv1()` 拒绝路径，协议页不可跳过 | 二/三 |

**回滚机制设计要求（A2 的实现口径）**

1. 全部写入先落 `staging/`，校验通过后才 **原子替换**；
2. 替换前把旧版本目录改名为 `.backup-<timestamp>/`；
3. 任一步失败 → 删除 `staging/`、恢复 `.backup-*`，向用户抛中文错误；
4. 装机清单（`install-manifest.json`）记录每个落盘文件，卸载/回滚**只删清单内的**；
5. `.backup-*/` 保留到下一次成功启动后再清理。

## 8. 板块增删流程

```powershell
# 1) 编辑 packaging/boards.json（id 必须匹配 ^[a-z][a-z0-9-]*$，且不重复）
# 2) 生成目录与 board.json 骨架（幂等，已有文件不覆盖）
node packaging/scripts/scaffold-boards.mjs
# 3) 手工补 board.json 的 contents / install.target，资产板块补 asset-manifest.json
# 4) 干跑校验（缺 board.json、依赖不存在、必装板块异常都会被拦）
node packaging/scripts/build.mjs
```

规则：
- `kind: "required"` 只允许一个（当前 `core`），且 `defaultSelected` 必须 `true`；
- `kind: "preview"` 默认不勾选，装上也只有一个占位页；
- `dependsOn` 只能引用已存在的板块 id（脚本会校验）。

## 9. 产物与发布

```powershell
node packaging/scripts/verify.mjs
# → 校验 artifacts/ 下每个文件名是否符合 filePattern
# → 全部合规时写 artifacts/SHA256SUMS.txt
```

| 退出码 | 含义 |
|---|---|
| 0 | 产物全部合规，哈希清单已生成 |
| 1 | 有产物但文件名不合规 / 哈希异常 |
| 2 | 无产物（阶段一属正常） |

发布时把 `SHA256SUMS.txt` 与产物一起上传，下载页展示**版本号 + 日期 + 哈希前 8 位**，学员可校对《下载者安装手册》第 2 节。

## 10. 占位板块如何填充（阶段三）

以 `boards/character-txzf/asset-manifest.json` 为例：

| 字段 | 含义 | 填充规则 |
|---|---|---|
| `assets[].name` | 资源名（立绘 / 表情差分 / 气泡框 / 语音） | 与美术交付清单一一对应 |
| `assets[].spec` | 规格（尺寸/格式/透明通道） | 不允许写「看情况」，必须可验收 |
| `assets[].count` | 文件数量 | 交付时改成真实数字 |
| `assets[].source` | 来源（美术 / 采购 / 生成） | 生成类需注模型与提示词位置 |
| `assets[].status` | `TODO` / `IN_PROGRESS` / `DONE` | **只有全 DONE 才能把 board 的 `status` 改成 `ready`** |

`board.json` 的 `status` 从 `placeholder` → `ready` 之前，`build.mjs` 会一直把它当占位处理（不阻断构建，但发布说明里必须标注「占位」）。

## 11. 已知坑（血泪版）

| 坑 | 现象 | 应对 |
|---|---|---|
| **Windows SmartScreen** | 未签名 exe 首次运行被拦「已保护你的电脑」 | 阶段三买证书签名；过渡期在下载页写清「更多信息 → 仍要运行」，并在手册配截图位 |
| **杀软误报** | 内置运行时/打包器释放文件被拦 | 提交误报申诉；产物与哈希公开；手册 FAQ 写清处置 |
| **路径含中文/空格** | 装配脚本路径解析失败 | 一律用 `path.join`，禁用字符串拼接；安装目录默认用户目录 |
| **系统 Node 与内置运行时冲突** | 学员机器上两个 Node 版本打架 | 便携版优先用内置；检测脚本只读，绝不改系统 PATH |
| **profile 独占** | `desktop` profile 由 Electron 应用独占，CLI 无法 boot/dump（本项目已踩） | 装配阶段只写 `package.json` 的 `dependencies` + `dsh.profile.bundles`，不尝试用 CLI 启动 desktop profile |
| **`dsh plugin add` 不写 bundles** | 只写依赖，插件永远不加载 | 装配器必须显式把 board 写进 `dsh.profile.bundles`（本项目已踩） |
| **版本与文件名不同步** | 手工改名导致哈希与版本对不上 | 只用 `version.mjs` 生成文件名，禁止手改 |

node packaging/runtime/detect-node.mjs      # 独立探针：Node 24.21.0 可用 → 退出码 0

node --check packaging/installer/shell/lib/detect-runtime.js

# 真实 Electron 自检（跑通 IPC、截图、写报告）
$env:DSH_TRAINING_SELFTEST = "1"; cd packaging\installer\shell
.\node_modules\electron\dist\electron.exe .
# → artifacts/qa/selftest-report.json（result: PASS）

> Electron 依赖的坑：`pnpm add electron` 默认**不跑 postinstall**，`node_modules/electron/dist` 会是空的。
> 处置：`package.json` 里加 `pnpm.onlyBuiltDependencies: ["electron"]`，再执行
> `node node_modules/electron/install.js`（配 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 更快）。
