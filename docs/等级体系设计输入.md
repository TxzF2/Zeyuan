## 1. 两条独立的等级轴

**关键决策（用户拍板）**：业务等级与管理档位**分开编号**，不混成一个阶梯。

### 1.1 业务等级 `LV0–LV1`（由 license 决定）

| 等级 | 名称 | 判定 | 能力 |
|---|---|---|---|
| **LV0** | 未授权访客 | 无有效 license | 浏览公开内容（任务列表、社区公开帖） |
| **LV1** | 学员（默认登录身份） | license 有效且含 `training:playground` | 领取/提交任务、编辑草稿、发帖、点赞 |

> 默认登录用户 = LV1 学员；`x-dsh-user` 缺省为 `local-user`。

### 1.2 管理档位 `P0 / P6 / P7 / P8`（由 `data/admins.json` 决定）

| 档位 | 名称 | 能力 |
|---|---|---|
| **P0** | 普通用户 | 无控制台权限 |
| **P6** | 工作区负责人 | 仪表盘、审计、板块启停（非核心）、用户列表 |
| **P7** | 项目负责人 | + 用户新建/禁用、档位调整（≤P7）、`training:review` 下发 |
| **P8** | 总师 | + `training:admin` 下发、发币、调整任何档位、停用 console 以外的一切 |

### 1.3 交叉矩阵（谁能做什么）

| 操作 | LV1 | P6 | P7 | P8 |
|---|---|---|---|---|
| 浏览公开内容 | ✅ | ✅ | ✅ | ✅ |
| 任务领取/提交、草稿、发帖、点赞 | ✅ | ✅ | ✅ | ✅ |
| 查看仪表盘 / 审计 | ❌ | ✅ | ✅ | ✅ |
| 板块启停（tasks/workbench/community） | ❌ | ✅ | ✅ | ✅ |
| 停用 core / console | ❌ | ❌（E-1106） | ❌ | ❌ |
| 新建用户 / 禁用用户 | ❌ | ❌ | ✅ | ✅ |
| 调整档位 | ❌ | ❌ | ✅（≤P7） | ✅（含 P8） |
| 下发 `training:review` | ❌ | ❌ | ✅ | ✅ |
| 下发 `training:admin` | ❌ | ❌ | ❌ | ✅ |
| 发币 | ❌ | ❌ | ❌ | ✅ |

## 2. 判定顺序（实现契约，阶段四不得改）

```
身份（x-dsh-user / 缺省 local-user）
  → 用户目录校验（未知自动登记；disabled 拒绝 E-1108）
  → 管理档位 P0/P6/P7/P8（admins.json）
  → 业务门禁 LV0/LV1（license scope: training:playground）
  → 业务规则（作者 / 领取人 / 发起人）
```

## 4. 与 D-005（评论）的关系

评论所需的最小依赖本轮已全部提供：

| 评论需要 | 已提供 |
|---|---|
| 用户身份 | ✅ `data/users.json` |
| 谁能否删/禁言 | ✅ 权限矩阵（LV4+ 拟用于评论管理，P7+ 用于全局） |
| 评论作者归属 | ✅ 用户 id |
| 内容可见性模式 | ✅ 复用 community 的 `canSee` 思路 |

阶段四做评论时**不需要再新增身份体系**。

## 5. 与 D-007 的关系

D-007（"谁登录都是管理员"）已收口：admin 只来自 `data/admins.json` 的显式绑定，
不再从整机 license 的 scope 推导。license 仅保留 LV0/LV1 业务门禁。
