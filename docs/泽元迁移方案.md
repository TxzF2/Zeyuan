# 《泽元迁移方案》——技术 id 全量改名（dsh-training-* → zeyuan-*）

| 项 | 内容 |
|---|---|
| 版本 | v1（2026-10-25） |
| 状态 | **P1 已实现**（迁移脚本 + 测试）；P2 待执行 |
| 原则 | 先数据后代码；先可回滚后不可逆；旧目录永不删除 |

## 1. 为什么要分两步

品牌改名（已完成）只动了**显示层**。技术 id 一动，影响 5 处运行时绑定：

| 绑定 | 后果 |
|---|---|
| 插件包名 `dsh-training-*` | 已装目录、profile `bundles`、`node_modules` junction 全部失配 |
| 事件命名空间 `dsh-training:*` | 历史事件日志与新事件割裂 |
| 状态目录 `%LOCALAPPDATA%\dsh-training` | 用户数据（任务/帖子/评论/钱包/中转文件）读不到 |
| 板块 id（core/tasks/console/…） | registry、check-boards、boards.json 全依赖 |
| license 绑定 | 授权按 subject/机器绑定，改名后需确认仍能验签 |

所以先做**数据迁移脚本**（可 dry-run、可回滚、幂等），再做代码改名。

## 2. P1 · 迁移脚本（已交付）

`packaging/scripts/migrate-zeyuan.mjs`

| 能力 | 说明 |
|---|---|
| dry-run 默认 | 只打印计划，不写盘 |
| `--apply` | 执行迁移 |
| `--force` | 新目录已存在时覆盖 |
| 迁移项 1 | 状态目录 `dsh-training` → `zeyuan`（复制，旧目录保留） |
| 迁移项 2 | `event-log.jsonl`：`dsh-training:*` → `zeyuan:*`；**旧信封（v/at/type）自动升级为 canonical（event/id/ts/actor/payload）** |
| 迁移项 3 | `mount-events.jsonl`：`plugin` 名 `dsh-training-*` → `zeyuan-*` |
| 迁移项 4 | profile `package.json`：`dependencies` 键与 `dsh.profile.bundles` 改名，**改写前备份** |
| 幂等 | 重复执行无变更、不追加备份（有测试） |
| 回滚 | 还原 `package.json.bak-<ts>` + 删除新状态目录 |

**测试**：`test/test-migrate-zeyuan.mjs`（5 组）：dry-run 不写盘 / apply 四项全做且旧目录保留 / 二次执行幂等 / 旧信封升级 / 纯改名函数。

**真机 dry-run 结果（2026-10-25）**：

```
[copy]    state-dir    复制 1482 个文件 → %LOCALAPPDATA%\zeyuan
[rewrite] event-log    事件 76 条，需改名 76 条（全部是旧信封，会一并升级）
[rewrite] mount-events 挂载记录 147 条，需改名 147 条
[rewrite] profile      dependencies 7 项 / bundles 7 项
```

## 4. 回滚

```powershell
# 1) 还原 profile 接线
Copy-Item "$env:USERPROFILE\.dsh\profiles\desktop\package.json.bak-<ts>" "$env:USERPROFILE\.dsh\profiles\desktop\package.json" -Force
# 2) 删除新状态目录（旧目录一直在，不删）
Remove-Item "$env:LOCALAPPDATA\zeyuan" -Recurse -Force
```

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 别人已装旧包，改名后失联 | P2.3 保留旧目录只读 fallback + 包内附迁移脚本 |
| 事件日志割裂 | 迁移脚本一次性改名；新旧并存期用 `event` 前缀识别 |
| license 失效 | P2.6 专项回归；subject 与机器绑定不改 |
| 迁移中断留下半成品 | 脚本只写新目录；中断重跑幂等 |
